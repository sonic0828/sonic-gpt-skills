# 游戏资产库提炼

把玩家能指认的对象作为条目。交付可打开的工作台、可复用的提炼输入与机器可读清单，覆盖范围以当前项目的证据为准。

1. **定范围与落点。** UI Kit 聚焦页面、弹窗、HUD、控件及其状态。完整资产库还需检查项目中的玩法物件、角色、场景、音频等，按实际对象分类。更新先读已有的 `catalog.json` 与 `manifest.json`，沿用原模式和 ID。优先沿用游戏已有的开发目录、截图和预览方式。检查导出配置；有打包风险时选用包外开发目录或用户指定的隔离目录。
2. **从两端找对象。** 顺着游戏入口、场景与绘制函数查到资源，再从素材目录和图集元数据反查使用处。程序绘制的控件记录函数和调用页。图集按对象记录帧名与区域，同一对象的几种外观归在一起。识别候选、归档和仅发现文件，动态加载的使用处只有查到依据才填写。优先从项目已有目录、配置或数据表批量收集同类条目，并明确遗漏或只抽查的范围。
3. **给出能说明用途的预览。** 静态图标用原图或图集裁切；需要观察格位、成盘、动画或布局时，优先复用已有的隔离渲染和固定状态。选择能解释对象的截图、短录像、音频或定位信息。只在确有材料时添加状态。仅有截图或录像时标为画面证据，记录文件、区域或时间点，代码与隐藏状态留空。使用内存数据或固定样本，避开真实支付、广告、存档与素材替换。
4. **生成和更新。** 按[清单格式](references/catalog.md)把本次完整盘点写入输出目录的 `catalog.json`，局部更新先合并到原输入。使用当前 SKILL.md 同目录的脚本，两个命令均以同一游戏根目录作为 `--project`。

   ```sh
   python3 "$SKILL_DIR/scripts/kit.py" build --project "$GAME" --out "$OUT"
   python3 "$SKILL_DIR/scripts/kit.py" check --project "$GAME" --out "$OUT"
   ```

5. **走一遍读者的路径。** 打开输出的 `index.html`，从分类或搜索进入一个对象，核对预览、状态、使用位置及原文件。带裁切区域的图要与原画面对照，确认截到目标对象。更新时检查具体增删改、人工字段和失联条目。交付入口、清单路径、覆盖范围、只可定位的对象、打包排除情况；将仅靠静态证据的结论标清楚。
